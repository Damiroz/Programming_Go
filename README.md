# Структура Go-проекта

## Цель работы
Освоить базовую организацию Go-проекта, научиться корректно распределять код по директориям и запустить минимальный HTTP-сервис.

## 🚀 Быстрый старт
```bash
go version
git --version
git clone https://github.com/<USER>/myapp.git
cd myapp
go run ./cmd/myapp
```

## 📁 Структура проекта
myapp/
├─ cmd/myapp/main.go
├─ internal/app/app.go
├─ internal/app/handlers/
├─ utils/logger.go
├─ utils/httpjson.go
└─ go.mod


## 🔍 Тестирование API
```bash
curl -i http://localhost:8080/

curl -i http://localhost:8080/ping

curl -i -H "X-Request-Id: demo-123" http://localhost:8080/ping

curl -i http://localhost:8080/fail

(Скрины находятся в папке utils)
```

## 🏗 Архитектура проекта

- cmd/

Содержит точки входа приложения. Каждый подкаталог соответствует отдельному исполняемому файлу. Такой подход сохраняет main.go минимальным и читаемым, вынося бизнес-логику в специализированные пакеты.

- internal/

Приватный код, недоступный для импорта из внешних проектов. Это обеспечивает инкапсуляцию реализации и предотвращает случайное использование внутренних компонентов.

- utils/

Вспомогательные функции общего назначения: логирование, работа с JSON и другие утилиты. Эти компоненты независимы от бизнес-логики и могут повторно использоваться в различных частях приложения.

- configs/

Шаблоны конфигурационных файлов для разных окружений. Упрощает настройку проекта и ускоряет onboarding новых разработчиков.

- api/

Спецификации и контракты API. Разделение интерфейсов и реализации повышает прозрачность архитектуры и упрощает интеграцию с внешними системами.

Каждая директория выполняет строго определённую роль: cmd/ управляет запуском, internal/ инкапсулирует логику, utils/ предоставляет утилиты, configs/ хранит настройки, api/ определяет интерфейсы взаимодействия. Такая организация кода способствует созданию понятных, поддерживаемых и масштабируемых проектов.
