## Контрольные вопросы

1. В чём разница между Docker-образом и контейнером?

Образ — это статическая сборка приложения со всеми зависимостями.  
Контейнер — это запущенный экземпляр образа, то есть процесс выполнения.

---

2. Для чего используется Dockerfile?

Dockerfile описывает шаги сборки образа: базовую систему, зависимости, копирование файлов и команду запуска.

---

3. Что такое multi-stage build?

Это подход, при котором сборка разделяется на несколько этапов, и в финальный образ попадает только результат сборки.

---

4. Почему multi-stage build удобен для Go?

Go компилируется в один бинарный файл, поэтому можно собрать его отдельно и перенести в минимальный образ без лишних зависимостей.

---

5. Зачем нужен .dockerignore?

Он исключает ненужные файлы из контекста сборки, ускоряя процесс и уменьшая размер образа.

---

6. Для чего используются переменные окружения?

Они позволяют менять конфигурацию приложения без пересборки образа.

---

7. Что делает -p в docker run?

Пробрасывает порт контейнера на хостовую машину.

---

8. Зачем нужен Docker Compose?

Он позволяет запускать несколько контейнеров одной командой через YAML-конфигурацию.

---

9. Почему контейнеризация удобна?

Она обеспечивает одинаковое окружение на любой машине.

---

10. Почему нельзя хранить секреты в образе?

Потому что образ может быть распространён, и секреты станут доступными. Лучше использовать переменные окружения.
